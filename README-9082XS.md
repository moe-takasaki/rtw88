# 9082XS port status

This branch starts from Igor Listopad's RTL8189ES `rtw88` work, PR #465 head `475584a581cb449a8616e0339ecb85bcb88c67aa`. The target device is SDIO `02e7:9082`, exposed by Lunar as `mmc2:0001:1`.

The first patch adds a separate `rtw_9082xs` SDIO module and maps its WLAN register window to `0x14000` instead of RTL8189ES's `0x10000`. Six read-only register comparisons on hardware showed that the old window returns `0xea`, while the new window returns live register values. Other SDIO address spaces are left unchanged. The module builds against Lunar `6.18.41-lunar`.

9082XS has its own chip description and MAC table. Initial comparison showed 91 of 92 shared byte values matched Igor's table after bit reversal, but the vendor table also has 40 byte addresses absent from Igor's and uses mixed 8-, 16- and 32-bit writes. The driver now replays all 49 recovered MAC write operations in their original order and width. A mechanical comparison against the diagnostic table confirmed exact agreement. Hardware readback after that diagnostic table confirmed `0x4026=0x82`, `0x4027=0xac`, and `0x4421=0xf0`. The new table also completed in the opt-in `rtw88` staged probe; runtime MAC behavior still needs validation.

The 9082XS chip description has its own power-on sequence. The SDIO transport now runs the same checked CMD52/CMD53 operations as the diagnostic module, including the final `0x4004` and `0x4100` enables. The RTL8188E revision register is not read before 9082XS power-on; a fixed single-RF-path description is used for this variant. The shutdown path now replays the vendor-derived preamble, low-power table, MCU stop, close table and final `0x401c=0x70`. A staged hardware probe returned through cleanup without an SDIO error, but shutdown register effects have not yet been read back; the generic register operations return no error directly. A first-error latch now catches SDIO transfer failures during staged initialization. The SDIO stop callback also skips interrupt-mask writes before an IRQ is claimed, avoiding the previously observed failed write to local address `0x14` during early probe cleanup.

The chip requests the privately installed `tilk/9082xs-nic.bin` instead of Igor's RTL8188E firmware. The loader treats it as a raw image without a legacy 32-byte header, selects its 4 KiB pages through register `0x82`, and checks each SDIO page transfer for errors. On 26 November, a staged `rtw88` probe after a box power cycle downloaded firmware without SDIO errors. The image itself is absent from this repository.

The 9082XS physical eFuse reader uses byte-width SDIO register accesses and bit-reverses the address byte, matching the diagnostic path that decoded 17 records and a valid MAC on hardware. The reader and logical-map decoder preserve empty extended headers and continue reading the physical region. The variant reads eFuse before downloading firmware, matching the diagnostic sequence. A staged hardware probe after the box power cycle decoded logical ID `0x9082` and MAC `b4:04:18:4d:50:82` without falling back to a random address.

The PHY table is now variant-specific: 284 ordered 32-bit operations, including bit-reversed and raw masked writes, each followed by the vendor's one-microsecond delay. A local entry-by-entry comparison matched the diagnostic table, and the changed module built against Lunar `6.18.41-lunar`. The AGC table has 130 raw 32-bit writes with the vendor's one-microsecond spacing, including the final two writes to `0x4c50`. The RF table has 92 raw 32-bit writes to `0x4840`, with the vendor's one-microsecond spacing and two 100-millisecond pauses. Both the checked diagnostic module and an opt-in staged `rtw88` probe completed MAC, PHY, AGC and RF table replay on the box without logged SDIO errors. This verifies transport and table replay, not calibration, receive, transmit or Wi-Fi operation.

Initialization is guarded by `experimental_hw_init=0` by default. With `experimental_hw_init=1`, the branch reads eFuse and downloads firmware, then deliberately returns `-EOPNOTSUPP` before interface registration. Passing `s9082c_stage_radio_tables=1` to `rtw_8188e.ko` additionally replays the 9082XS MAC, PHY, AGC and RF tables while the chip is powered, checks the first SDIO register-access error after each table, and then returns through the same guard. The optional stage completed on hardware and all four modules unloaded cleanly. Radio calibration, receive, transmit and shutdown register effects remain unverified.

For a registration-only experiment, also pass `experimental_register_hw=1` to `rtw_9082xs.ko`. This opts out of the post-eFuse stop and registers the PHY, but does not bring the interface up. The 9082XS WLAN register window is inaccessible after the eFuse phase powers the chip off, so channel configuration and TX-power programming are deferred until power is on; interrupt-mask writes are skipped during removal if it is off. On a clean boot, two successive load/unload cycles registered `wlan0` with eFuse MAC `b4:04:18:4d:50:82`, kept it down, and logged no SDIO errors. A previous build without the TX-power guard produced repeated SDIO timeouts during regulatory notification and left the chip unable to re-probe until reboot. Interface start, calibration, receive and transmit are not yet validated.

`experimental_start_once=1` additionally runs `rtw_power_on()` and `rtw_power_off()` during probe after registration, with the interface still down. Two successive hardware runs completed this MAC/PHY/HCI initialization and shutdown without logged SDIO errors, and all modules unloaded. This checks the core power path but does not exercise the mac80211 start callback, periodic calibration or traffic.

The latest build completed after BitBake recreated `Module.symvers`, and its staged table replay was retested on the box. The driver reported the expected eFuse MAC, completed MAC/PHY/AGC/RF table replay without an SDIO error, and stopped before interface registration. All four modules unloaded successfully and SDIO `02e7:9082` remained visible.

The vendor binary's `TDB_S9082_Init_PHY_PG` loads the same six rate-power entries as the inherited RTL8188E table after translating its `0x4e00`-series register addresses to `0xe00`-series `rtw88` offsets. Its 168 regulatory TX-power records contain all 143 inherited limit records with identical fields and values. The remaining 25 records explicitly specify index `63`, which is the default for missing limits in `rtw88`. The packed eFuse difference byte uses signed four-bit values; the board's `0xbf` decodes to low nibble `-1` and high nibble `-5`, as in the inherited little-endian layout. These comparisons validate table contents and parsing layout, not RF output power on hardware.

Next: adapt the chip-specific runtime register sequence and calibration before starting the interface or testing traffic. Keep the extracted firmware outside the repository until redistribution rights are established.
